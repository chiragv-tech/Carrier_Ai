# CareerAI Viva Preparation

## 60-second project introduction
“CareerAI is a local-first AI career intelligence platform built with Python and Streamlit. It extracts text from PDF resumes, detects common skills, compares resume text with sample job descriptions using TF-IDF and cosine similarity, and generates role-based skill gaps and learning roadmaps. SQLite stores accounts and saved analyses, Plotly displays analytics, and users can export PDF and CSV reports. A rule-based assistant provides offline guidance, so no paid LLM API is required. The displayed match scores are text-similarity estimates, not hiring probabilities.”

## Common viva questions and answers

### 1. Why did you build CareerAI?
Students often need help connecting what is in their resume to job descriptions and learning priorities. CareerAI structures that exploration; it does not replace a human career advisor or recruiter.

### 2. What is TF-IDF?
TF-IDF stands for Term Frequency–Inverse Document Frequency. It weights terms based on their frequency in a document and how distinctive they are across the document collection.

### 3. Why use cosine similarity?
Cosine similarity compares the direction of two numeric vectors. It is commonly used for document similarity and is less directly affected by vector magnitude than a raw dot product.

### 4. Is the job match score a probability?
No. It is a percentage-scaled text-similarity estimate. It is not trained or calibrated to predict interviews, offers, or hiring probability.

### 5. Is TF-IDF a deep learning model?
No. It is a classical text vectorization technique. This project uses a traditional machine-learning / information-retrieval approach rather than a neural language model.

### 6. How does resume parsing work?
PyMuPDF extracts selectable text from each PDF page. Rules and regular expressions detect skill vocabulary and common section headings. The method is lightweight but may miss skills expressed with unfamiliar wording or resumes with unusual layouts.

### 7. What happens with a scanned PDF?
The current version warns when very little text is extractable. It does not include OCR; a scanned resume should be converted to a text-searchable PDF first.

### 8. How are missing skills identified?
The app compares detected skills with a configurable checklist for the selected role. Any configured skill not detected in the resume is listed as a potential gap. “Not detected” does not prove the user lacks that skill.

### 9. How is the roadmap personalized?
The role selects a predefined learning path. For each stage, the app highlights checklist skills not detected and gives a practical activity. The roadmap is rule-based, not generated by a trained recommender.

### 10. Why SQLite?
SQLite is a lightweight relational database included with Python, easy to run locally, and suitable for a small single-machine prototype without a separate database server.

### 11. How are passwords stored?
The app stores a salted PBKDF2-HMAC-SHA256 hash with an iteration count. It does not store plain-text passwords. A production service would also need rate limiting, secure sessions, and broader security controls.

### 12. How is user data separated?
Saved analysis queries filter by the authenticated user's ID. Loading and deletion require both the analysis ID and the user ID. This is application-level isolation for a local demo, not a substitute for a production security audit.

### 13. Why does the assistant not use an LLM?
The requirement is to function without paid APIs. The rule-based assistant is predictable, offline, easy to explain, and answers a limited set of career question types. It is less flexible than a language model.

### 14. What are the limitations?
Fixed skill vocabulary, heuristic section extraction, no OCR, fictional job descriptions, rule-based roadmaps, and text-similarity scores that depend on wording. It should not be used as an automated hiring decision system.

### 15. How would you improve the ML component?
Build a labelled resume–job relevance dataset, define evaluation criteria, compare TF-IDF baselines with semantic embeddings, use train/test splits, and report ranking metrics such as Precision@K or nDCG. Avoid claiming quality without evaluation evidence.

### 16. What metrics could evaluate matching quality?
With labelled relevant/non-relevant pairs, ranking metrics such as Precision@K, Recall@K, Mean Reciprocal Rank, and nDCG can evaluate whether relevant roles appear near the top. The current sample app has no labelled benchmark, so it does not claim measured model accuracy.

### 17. Why use Streamlit?
It lets a Python developer create interactive data applications quickly, with forms, file upload, charts, session state, and download controls without building a separate JavaScript frontend.

### 18. Why Plotly?
Plotly provides interactive charts that can show hover values and adapt to user interaction, making dashboard metrics easier to explore.

### 19. What happens when a resume is analyzed?
The PDF is validated, text is extracted, skills and sections are detected, resume/job documents are vectorized, cosine similarity is calculated, jobs are sorted, a role gap and roadmap are generated, and the analysis is saved to SQLite for the signed-in user.

### 20. What makes the project responsible?
It describes scores honestly, uses fictional sample roles, runs locally, does not invent missing skills, and tells users that not detecting a skill is not proof they lack it. It is guidance rather than a hiring decision.

## Demo sequence for evaluation
1. Show the landing page and explain the local-first stack.
2. Register a demo account and sign in.
3. Upload a sample text-searchable PDF resume.
4. Show extracted skills, detected sections, and suggestions.
5. Explain the top match and point out the similarity disclaimer.
6. Open Skill Gap & Roadmap and choose a target role.
7. Ask the assistant about missing skills.
8. Download both PDF and CSV reports.
9. Open Saved Analyses and load the record.
10. Open Project Guide and explain limitations and future work.

## Questions you should be ready to demonstrate
- Why a role ranked first: explain overlapping weighted terms, not a claim of guaranteed fit.
- Why a skill appears missing: it was not detected by the current vocabulary rules.
- Why results vary with wording: TF-IDF is based on terms and phrases.
- Where data is saved: `careerai.db` in the project folder.
- How to add a role: edit `data/jobs.json` and restart the app.
